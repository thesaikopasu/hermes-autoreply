# ربات پاسخ‌خودکار تلگرام (یوزربات)

دستیار شخصی تلگرام که وقتی نیستی، از **حساب خودت** (یوزربات — نه حساب بات) به پیام‌های خصوصی جواب می‌دهد. یک حساب دوم (واتچر) وضعیت آنلاین‌بودن تو را می‌خواند تا تا وقتی پای کیبورد هستی هیچ جوابی فرستاده نشود. همه‌چیز به یک **بات کنترل** که با @BotFather می‌سازی گزارش می‌شود: همان چت خصوصی، هم پنل کنترل توست و هم فید اعلان‌ها — با دکمه‌های اینلاین برای نادیده‌گرفتن یک نفر، جواب‌دادن به‌جای خودت، یا خوانده‌شده‌کردن پیام.

**🇬🇧 [English README](README.md)**

**ویژگی‌ها**

- جواب از حساب خودت فرستاده می‌شود، پس طرف مقابل یک جواب معمولی از تو می‌بیند، نه از یک بات.
- مبتنی بر حضور: حساب دوم (واتچر) وضعیت آنلاین تو را می‌خواند، پس تا وقتی پای کیبوردی چیزی جواب داده نمی‌شود.
- حالت‌های «اخیراً آنلاین بودی» هم هست؛ پیش‌فرض روی حضور است و اگر حضور در دسترس نباشد به معیار بی‌کاری کامپیوتر برمی‌گردد.
- محافظت از فلود: کسی که در یک بازه بیشتر از N پیام بفرستد، به‌جای جواب مؤدبانه هشدار اسپم می‌گیرد — و این بررسی **قبل از همه‌ی قانون‌های دیگر** اجرا می‌شود، پس حتی وقتی آنلاینی هم اسپم جواب می‌گیرد.
- کول‌داون هر شخص، سقف پاسخ در ساعت، لیست نادیده، وایت‌لیست و لیست گروه‌های مجاز — همه بدون ری‌استارت و زنده قابل تغییرند.
- بات کنترل به‌عنوان پنل: وضعیت، روشن/خاموش، لیست نادیده، گروه‌های مجاز، متن پاسخ‌ها، تنظیمات کول‌داون و اسپم، حالت گزارش، گزارش روزانه و فهرست خطاهای اخیر.
- گزارش‌ها فقط به چت خصوصی تو با بات کنترل می‌روند؛ محتوای پیام هیچ‌وقت در فایل لاگ نوشته نمی‌شود.
- داده‌ها (دیتابیس، لاگ‌ها، فایل pause) داخل `DATA_DIR` می‌مانند، پس کانتینر می‌تواند state خودش را روی یک والیوم نگه دارد.

**چه کارهایی نمی‌کند:** پورت باز نمی‌کند، اتصال ورودی نمی‌پذیرد، وب‌سرور ندارد و در زمان اجرا هیچ چیزی از تو نمی‌پرسد. سشن از متغیر محیطی خوانده می‌شود، پس `python auto_reply.py` بدون یک کلید هم بالا می‌آید و کار می‌کند.

## چطور کار می‌کند

یک پروسه، دو کلاینت تلگرام:

| کلاینت | حساب | نقش |
| --- | --- | --- |
| **یوزربات** | حساب انسانی خودت (`SESSION_STRING`) | پیام‌های خصوصی را می‌گیرد، جواب را به‌جای تو می‌فرستد، گروه‌های مجاز را می‌خواند |
| **بات کنترل** | باتی که با @BotFather می‌سازی (`BOT_TOKEN`) | همه‌ی اعلان‌ها را به تو می‌رساند و پنل کنترل را اجرا می‌کند — فقط به `OWNER_ID` جواب می‌دهد |
| *واتچر* (اختیاری) | حساب انسانی دوم (`WATCHER_SESSION_STRING`) | فقط وضعیت آنلاین تو را می‌خواند؛ یک حساب نمی‌تواند وضعیت خودش را ببیند |

همه‌چیز زیر `DATA_DIR` نوشته می‌شود:

| فایل | محتوا |
| --- | --- |
| `state.db` | SQLite: تنظیمات، شمارنده‌ی هر شخص، لیست نادیده، گروه‌های مجاز، حافظه‌ی خطاها |
| `auto_reply.log` | لاگ زمان‌دار (تعداد، کد خطا، آیدی ماسک‌شده — هیچ‌وقت متن پیام) |
| `offline.jsonl` | ژورنال تغییر وضعیت آنلاین/آفلاین |
| `pause.flag` | تا وقتی این فایل هست، هیچ جوابی فرستاده نمی‌شود |

فایل `config.json` کنار کد **مقادیر پیش‌فرض** و متن پاسخ‌ها را نگه می‌دارد؛ در اولین اجرا به `state.db` منتقل می‌شود و از آن به بعد دیتابیس مرجع است. تغییر یک تنظیم از پنل، بی‌درنگ روی رفتار اثر می‌گذارد، بدون ری‌استارت.

## پیش‌نیازها

- **پایتون ۳٫۱۰ یا بالاتر** (ایمیج داکر از ۳٫۱۲ استفاده می‌کند).
- یک حساب تلگرام (همانی که می‌خواهد جواب بدهد) و `api_id` / `api_hash` آن.
- یک بات ساخته‌شده با **@BotFather** (رایگان، یک دقیقه‌ای).
- پکیج‌ها: `pip install -r requirements.txt` (telethon، python-dotenv، python-socks، cryptg).

## راه‌اندازی محلی

**۱. گرفتن `API_ID` و `API_HASH`** — برو به <https://my.telegram.org>، با شماره‌ی همان حسابی که می‌خواهد جواب بدهد لاگین کن، برو به *API development tools*، اگر اپلیکیشنی نداری بساز و آن دو مقدار را کپی کن.

**۲. گرفتن `SESSION_STRING`** — این همان لاگین حساب انسانی است، در یک خط:

```bash
python generate_session.py
```

اگر این اسکریپت را نداشتی، این را در یک فایل موقت (`gen_session.py`) بگذار و یک‌بار اجرا کن:

```python
from telethon.sync import TelegramClient
from telethon.sessions import StringSession

api_id = int(input("api_id: "))
api_hash = input("api_hash: ")
with TelegramClient(StringSession(), api_id, api_hash) as client:
    print("\nSESSION_STRING:\n" + client.session.save() + "\n")
```

شماره‌ی موبایل و کد ورودی را می‌پرسد و رشته را **یک‌بار** نشان می‌دهد. با آن مثل رمز عبورت رفتار کن — هر کسی داشته باشدش، به‌جای تو لاگین است. فایلی که اجرا کردی را کامیت نکن؛ `.gitignore` خودش `*.session` و `.env` را کنار گذاشته.

**۳. گرفتن `BOT_TOKEN`** — در تلگرام به **@BotFather** پیام بده: `/newbot`، یک اسم و یوزرنیم بده و توکنی که می‌دهد را کپی کن. این بات پنل کنترل توست؛ نیازی نیست به هیچ گروهی اضافه شود.

**۴. گرفتن `OWNER_ID`** — آیدی عددی خودت. به **@userinfobot** هر پیامی بده و عددی که جواب می‌دهد را بردار. بات کنترل **فقط** به همین حساب جواب می‌دهد.

**۵. باز کردن بات** — در چت خصوصی با بات جدیدت **/start** را بزن، وگرنه تلگرام اجازه نمی‌دهد به تو پیام بدهد.

**۶. تنظیم و اجرا**

```bash
cp .env.example .env      # then fill in the five required values
pip install -r requirements.txt
python auto_reply.py
```

هنگام بالا آمدن، یک خط سلامت چاپ می‌شود، مثلاً:

```
2026-01-01 12:00:00  === auto-reply bot v2 starting ===
2026-01-01 12:00:01  owner: id=123456789 @yourname name='You'
2026-01-01 12:00:02  notify: control bot ready (owner 1234***789)
2026-01-01 12:00:02  config: enabled=True mode=presence delay=5s cooldown=10m spam>3/30m report=offline_only daily=23:00 control_bot=ok
```

اگر بات کنترل نتواند به تو برسد، لاگ در یک خط می‌گوید و یوزربات به کارش ادامه می‌دهد: بات را در تلگرام باز کن و یک‌بار /start بزن.

بررسی‌های مفید که به اتصال تلگرام نیاز ندارند: `python auto_reply.py --env-check`، `--db-check`، `--commands-check`، `--test-decisions`، `--daily-preview`. وقتی اعتبارنامه‌ها سر جایشان باشند، `--presence-check` نشان می‌دهد کدام حساب‌ها وصل می‌شوند و الان جزو «آفلاین» حساب می‌شوی یا نه، و `--self-test` کل مسیر جواب‌دادن را تست می‌کند.

## متغیرهای محیطی

همه‌ی تنظیمات در زمان اجرا از محیط خوانده می‌شوند. `python-dotenv` اگر فایل `.env` باشد آن را هم می‌خواند (متغیر واقعی محیط همیشه برنده است)؛ برای همین اجرای محلی به آن فایل نیاز دارد و سرور نه.

| متغیر | لازم؟ | پیش‌فرض | معنی |
| --- | --- | --- | --- |
| `API_ID` | بله | — | آیدی عددی API حساب انسانی، از <https://my.telegram.org> → *API development tools*. `TELEGRAM_API_ID` هم به‌عنوان نام قدیمی پذیرفته می‌شود. |
| `API_HASH` | بله | — | هش API از همان صفحه. `TELEGRAM_API_HASH` هم پذیرفته می‌شود. |
| `SESSION_STRING` | بله | — | `StringSession` تلثون از حسابی که جواب می‌فرستد. این **خودِ لاگین** است — محرمانه نگهش دار. |
| `BOT_TOKEN` | بله | — | توکن بات کنترل، از @BotFather. فقط برای پنل و اعلان‌ها. |
| `OWNER_ID` | بله | — | آیدی عددی تلگرام تو. تنها حسابی که بات کنترل جوابش را می‌دهد و تنها چتی که گزارش به آن می‌رود. `OWNER_IDS`، `ADMIN_ID` و `ADMIN_IDS` هم پذیرفته می‌شوند. |
| `DATA_DIR` | خیر | `./data` (ایمیج داکر `/data` می‌گذارد) | پوشه‌ی `state.db`، `auto_reply.log`، `offline.jsonl` و `pause.flag`. روی والیوم مانت‌شده تنظیمش کن. |
| `WATCHER_SESSION_STRING` | خیر | خالی | `StringSession` حساب انسانی دوم که **فقط** برای خواندن وضعیت آنلاین تو استفاده می‌شود. خالی باشد: واتچر به فایل سشن محلی برمی‌گردد و تشخیص به بی‌کاری کامپیوتر تنزل می‌کند. |
| `REPORT_MODE` | خیر | `offline_only` | `all` هر پیام ورودی را گزارش می‌دهد، `offline_only` فقط وقتی نیستی. در پنل هم هست: *گزارش‌ها*. |
| `COOLDOWN_MINUTES` | خیر | `10` | دقیقه‌های لازم قبل از جواب دوباره به یک نفر. `/cooldown <دقیقه>` و پنل *تنظیمات* هم همین را دارند. |
| `TIMEZONE` | خیر | `Asia/Tehran` | منطقه‌ی زمانی برای ساعت‌ها و زمان‌بندی گزارش روزانه. |
| `LOG_LEVEL` | خیر | `INFO` | `DEBUG` / `INFO` / `WARNING` / `ERROR` برای فایل لاگ. |
| `PROXY` | خیر | خالی | پروکسی برای شبکه‌ی فیلترشده: `socks5://user:pass@host:port`، `http://host:port`، یا `host:port:secret` برای MTProxy. |

مقادیر رفتاری (`report_mode`، `cooldown_minutes`، آستانه و بازه‌ی اسپم، متن پاسخ‌ها، ساعت گزارش روزانه) در `state.db` زندگی می‌کنند و از `config.json` مقدار اولیه می‌گیرند، و از پنل بات کنترل زنده ویرایش می‌شوند. گذاشتن نسخه‌ی محیطی‌شان یعنی «پیش‌فرض استقرار تازه»، نه بازنویسی اجباری چیزی که دیتابیس دارد.

## دیپلوی روی Railway

ریپو همین‌طور که هست دیپلوی می‌شود: `railway.json` بیلدر `Dockerfile` را انتخاب می‌کند و هیچ سکرت زمان بیلی هم لازم نیست.

۱. **New Project** → **Deploy from GitHub repo**.
۲. **آدرس ریپو** را بچسبان (یا از لیست گیت‌هابت انتخابش کن) و بگذار Railway ایمپورت کند.
۳. برو به سرویس → **Variables** و پنج متغیر لازم را اضافه کن: `API_ID`، `API_HASH`، `SESSION_STRING`، `BOT_TOKEN`، `OWNER_ID`. هر کدام از اختیاری‌ها را هم خواستی اضافه کن (`DATA_DIR`، `REPORT_MODE`، `COOLDOWN_MINUTES`، `TIMEZONE`، `LOG_LEVEL`، `PROXY`، `WATCHER_SESSION_STRING`) — هیچ‌وقت داخل ریپو نگذارشان.
۴. **Add a Volume** به سرویس و آن را روی مسیر `DATA_DIR` مانت کن — یعنی `/data` که ایمیج می‌گذارد. بدون والیوم، دیتابیس در هر دیپلوی دوباره ساخته می‌شود و همه‌ی شمارنده‌ها و تنظیمات از دست می‌رود.
۵. **Deploy** و لاگ‌ها را ببین. شروع سالم با خط `config: …` تمام می‌شود.

دو نکته‌ی مخصوص این اپ:

- **بدون پورت ورودی و بدون دامنه.** هر دو کلاینت رو به بیرون به تلگرام وصل می‌شوند؛ هیچ‌چیز گوش نمی‌دهد. اگر پورت یا دامنه‌ی عمومی اضافه کنی، فقط سطح حمله اضافه کرده‌ای. برای همین `HEALTHCHECK` ایمیج به‌جای پروب پورت، زنده‌بودن پروسه و دسترسی نوشتن به `DATA_DIR` را چک می‌کند.
- **ری‌استارت‌ها خودکارند.** `restartPolicyType: ON_FAILURE` با ۱۰ تلاش، و پروسه طوری نوشته شده که هیچ‌وقت روی خطای تلگرام خارج نشود — قطعی لاگ می‌شود و دوباره تلاش می‌کند.
- Railway والیوم را با کاربر root مانت می‌کند در حالی که ایمیج با کاربر غیر روت اجرا می‌شود؛ اگر دیتابیس ساخته نشد (لاگ خطای نوشتن روی `/data` را نشان می‌دهد) متغیر سرویس **`RAILWAY_RUN_UID=0`** را بگذار.

همچنین می‌توانی همین ایمیج را روی هر VPS لینوکسی اجرا کنی:

```bash
docker build -t hermes-autoreply .
docker run -d --name hermes --env-file .env -v hermes_data:/data hermes-autoreply
```

یا بدون داکر، با `deploy/hermes.service` (یونیت systemd آماده) در `deploy/README-deploy.md` توضیح داده شده است.

## پنل بات کنترل

باتت را در تلگرام باز کن و **/menu** بزن. همه‌ی صفحه‌ها دکمه‌ی اینلاین‌اند، هر تغییر بی‌درنگ اعمال می‌شود و آیدی‌ها ماسک‌شده نشان داده می‌شوند (`1234***789`). بات هر فرستنده‌ای که در `OWNER_ID` نباشد را نادیده می‌گیرد — بدون جواب، پس غریبه حتی نمی‌فهمد وجود دارد.

| صفحه | چه می‌توانی بکنی |
| --- | --- |
| **منوی اصلی** | روشن/خاموش کردن پاسخ‌خودکار، رفتن به هر صفحه، بستن پنل |
| **وضعیت** | نگاه زنده: روشن‌بودن، حالت تشخیص، کول‌داون، قانون اسپم، حالت گزارش، ساعت گزارش روزانه، تعداد افراد نادیده و گروه‌های مجاز، شمارنده‌های دیتابیس، پیام‌های امروز |
| **متن پاسخ** | ویرایش جواب معمولی، هشدار اسپم و متن گروه؛ `{name}` با اسم طرف مقابل عوض می‌شود |
| **لیست نادیده** | اضافه/حذف کردن افراد (آیدی عددی یا `@یوزرنیم`) تا هیچ‌وقت جواب نگیرند |
| **گروه‌ها** | اضافه/حذف گروه (آیدی مثل `-100…` یا `@یوزرنیم` وقتی بات عضو است) که متن گروه در آن‌ها استفاده شود |
| **تنظیمات** | کول‌داون هر شخص، آستانه‌ی اسپم، بازه‌ی اسپم، حالت تشخیص (حضور / بی‌کاری / آفلاین) |
| **گزارش‌ها** | حالت گزارش (`all` / `offline_only`)، ساعت گزارش روزانه، روشن/خاموش گزارش روزانه، گزارش خطاها، پیام شروع |
| **خطاها** | آخرین خطاها و یک دکمه برای پاک‌کردن فهرست |

دکمه‌های اعلان، روی هر پیام گزارش‌شده: **🚫 نادیده‌گرفتن این کاربر**، **✍️ جواب دادن به‌جای Hermes** (متنت را می‌نویسی و به‌جای تو فرستاده می‌شود)، **✅ خوانده‌شده**.

اگر ترجیح می‌دهی تایپ کنی، دستورهای متنی: `/menu`، `/status`، `/on`، `/off`، `/ignore <آیدی یا @یوزرنیم>`، `/unignore <آیدی یا @یوزرنیم>`، `/mode all|offline_only`، `/cooldown <دقیقه>`، `/help`، `/cancel`.

## امنیت

- **هیچ‌وقت `.env` را کامیت نکن.** `.gitignore` فایل `.env`، هر `*.session` و پوشه‌ی `data/` را کنار گذاشته؛ `.env.example` فقط اسم و کامنت دارد. اگر فورک کردی، قبل از اولین پوش `git status` بزن.
- **رشته‌ی سشن به‌قدر لاگینت قدرت دارد.** هر کسی `SESSION_STRING` (یا `WATCHER_SESSION_STRING`) را داشته باشد، بدون رمز و کد می‌تواند پیام‌هایت را بخواند و بفرستد. از ریپو، از اسکرین‌شات و از گزارش باگ بیرون نگهش دار.
- **اگر لو رفت، باطلش کن:** تلگرام → *تنظیمات* → *دستگاه‌ها* → آن سشن را پایان بده. بعد یک `SESSION_STRING` تازه بساز و متغیر را عوض کن. قدیمی همه‌جا از کار می‌افتد.
- **`BOT_TOKEN` را هم خصوصی نگه دار** — آن پنل کنترل توست؛ یک غریبه با توکن می‌تواند رابط پنل را ببیند (هرچند چت تو به `OWNER_ID` گره خورده).
- کد فقط تعداد، کد خطا و آیدی ماسک‌شده را لاگ می‌کند. متن اعلان‌ها محتوای پیام را دارد ولی فقط به چت خصوصی تو با بات کنترل می‌رود، هیچ‌وقت به فایل لاگ.
- پروسه را با کاربر غیر روت اجرا کن (ایمیج داکر همین کار را می‌کند) و والیوم را فقط به همان کاربر بده.

| `auto_reply.py` | نقطه‌ی ورود: `python auto_reply.py` (به‌همراه بررسی‌های `--…-check`) |
| `bot.py` | سیم‌کشی: هندلرها، قانون‌های تصمیم، نظارت |
| `store.py` | `state.db`: تنظیمات، شمارنده‌ها، لیست نادیده، گروه‌ها، حافظه‌ی خطا |
| `tg.py` | اعتبارنامه‌ها، کلاینت‌ها، ارسال ایمن، ترجمه‌ی خطاها |
| `presence.py` | حساب واتچر، تایمر آفلاین خودکار، فالبک بی‌کاری کامپیوتر |
| `notify.py` | اعلان‌ها به مالک از طریق بات کنترل |
| `panel.py` | پنل کنترل با دکمه‌های اینلاین |
| `reports.py` | گزارش پیام، گزارش روزانه، گزارش خطا |
| `commands.py` | دستورهای متنی |
| `paths.py` | تنها جایی که `DATA_DIR` و فایل‌های داخلش را حل می‌کند |
| `config.json` | تنظیمات و متن‌های پیش‌فرض که به دیتابیس منتقل می‌شوند |
| `Dockerfile`، `Procfile`، `railway.json` | دیپلوی (بیشتر در `deploy/README-deploy.md`) |
| `deploy/hermes.service` | یونیت systemd برای VPS لینوکسی ساده |
